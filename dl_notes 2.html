1. Introduction to makemore

Welcome to the foundational masterclass on language modeling. Following the pedagogical philosophy established in micrograd, this repository—titled makemore—is built entirely from scratch. The goal is to demystify every single line of code and mathematical operation that powers modern language models. We will not hide behind high-level abstractions like nn.Module or nn.CrossEntropyLoss until we have written their equivalents out manually.

As the name implies, makemore takes a given dataset and learns to generate more instances that share the exact statistical and structural properties of the original data. By the end of this broader series, the exact same concepts we learn here will scale up to a Transformer architecture equivalent to OpenAI's GPT-2.

The Dataset: names.txt

The canonical dataset used for this lecture is a simple text file: names.txt. This file contains 32,000 unique human names. We will train our language model to understand the character-level structure of these names so it can synthesize brand-new, unique names that sound phonetically plausible.

2. Data Loading and Vocabulary Exploration

We start in a blank Jupyter notebook. Our first step is to read the data, unpack it, and understand its basic properties. 

# Read the names dataset into a single string and split by lines
words = open('names.txt', 'r').read().splitlines()

# Inspect the first 10 entries
print(words[:10])
# Output: ['emma', 'olivia', 'ava', 'isabella', 'sophia', 'charlotte', 'mia', 'amelia', 'harper', 'evelyn']

print("Total names:", len(words))
print("Shortest name length:", min(len(w) for w in words))
print("Longest name length:", max(len(w) for w in words))

The exploration confirms we have 32,033 names. The shortest names are 2 characters long, and the longest is 15 characters.

3. The Bigram Language Model: Core Intuition

A character-level language model attempts to predict the next character in a sequence given the history of previous characters. Every single word in our dataset is actually a packed sequence of multiple training examples.

Take the name isabella. It teaches the model several things:

  • Names often start with i.
  • Given i, the next character is often s.
  • Given isab, the next character is often e.

In a Bigram Language Model, we make a massive simplifying assumption: we assume that the next character depends only on the immediately preceding character. We drop all context except the single previous character. We model local structure only.

Extracting Bigrams using Python's zip

To teach the model about word boundaries, we must pad each word with a special Start-Of-Word (<S>) and End-Of-Word (<E>) token. In this lecture, we simplify this by using a single period . to represent both boundaries. 

# Extracting bigrams from a padded string
for w in words[:1]:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        print(f'{ch1} -> {ch2}')

# Output for 'emma':
# . -> e
# e -> m
# m -> m
# m -> a
# a -> .

4. The Statistical Counting Approach

Before we use neural networks, we will build the model by explicitly counting character co-occurrences. We iterate through the entire dataset and record how often character $Y$ immediately follows character $X$.

We store these counts in a 2D PyTorch tensor $N$ of size $27 \times 27$ (26 alphabet characters + 1 special token). To index into this tensor, we need string-to-integer (stoi) and integer-to-string (itos) mapping dictionaries. 

import torch

# Create a 27x27 tensor initialized to zeros for storing bigram frequency counts
N = torch.zeros((27, 27), dtype=torch.int32)

# Create mapping dictionaries
chars = sorted(list(set(''.join(words))))
stoi = {s:i+1 for i,s in enumerate(chars)}
stoi['.'] = 0
itos = {i:s for s,i in stoi.items()}

# Populate the counts matrix
for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        ix1 = stoi[ch1]
        ix2 = stoi[ch2]
        N[ix1, ix2] += 1

Plotting the Counts Matrix

In the lecture, we visualize N using matplotlib.pyplot.imshow and loop over the cells to draw the text strings (e.g., "a" followed by "b" and the exact count number). This gives us a beautiful heat map showing that certain combinations (like vowels following consonants) are highly frequent, while others (like 'q' followed by 'q') are virtually non-existent.

5. Probability Distributions and Broadcasting Semantics

Raw counts cannot be used directly to generate data. We must normalize these counts into probabilities. The probability of character $j$ following character $i$ is the count of bigram $(i, j)$ divided by the sum of all bigrams starting with $i$. 

# Convert counts to floats
P = N.float()

# Normalize rows
P /= P.sum(1, keepdim=True)

Deep Dive: Broadcasting and keepdim=True

This single line of code is notoriously dangerous in PyTorch if you don't understand broadcasting semantics.

P.sum(1) computes the sum across the 1st dimension (columns). If you do not specify keepdim=True, PyTorch strips the dimension, returning a 1D tensor of shape (27).

When you compute P / P.sum(1), PyTorch tries to broadcast the 1D tensor (27) against the 2D tensor (27, 27). According to broadcasting rules, it aligns them from the right. It will treat the 1D tensor as a row vector (1, 27) and divide column-wise, which is a mathematical disaster!

By using keepdim=True, the sum tensor has shape (27, 1). PyTorch correctly broadcasts this column vector horizontally, dividing each row by its respective row sum. Always verify tensor shapes when broadcasting!

Sampling the Model

With the probability matrix P, we can now "make more" names using PyTorch's multinomial sampler. 

g = torch.Generator().manual_seed(2147483647)

for i in range(5):
    out = []
    ix = 0
    while True:
        p = P[ix]
        # Sample an index from the probability distribution
        ix = torch.multinomial(p, num_samples=1, replacement=True, generator=g).item()
        out.append(itos[ix])
        if ix == 0: # Hit the end token
            break
    print(''.join(out))

6. Model Evaluation: Negative Log-Likelihood (NLL)

How do we evaluate the quality of our model? We measure the Likelihood of the training data under the model's assigned probabilities.

If the model is good, it will assign high probabilities to the bigrams that actually appear in the training set. The overall likelihood of the dataset is the product of all individual bigram probabilities:

$$ \text{Likelihood} = \prod_{i=1}^{N} P(\text{target}_i \mid \text{input}_i) $$

Because probabilities are between 0 and 1, multiplying thousands of them together will cause numerical underflow. Therefore, we take the logarithm. The log of a product is the sum of the logs.

$$ \log(\text{Likelihood}) = \sum_{i=1}^{N} \log P(\text{target}_i \mid \text{input}_i) $$

Log probabilities are negative numbers (since $\log(1) = 0$ and $\log(x < 1) < 0$). In machine learning, we like to minimize loss functions. So we invert the sign to get Negative Log-Likelihood (NLL). Finally, we average it over the entire dataset: 

log_likelihood = 0.0
n = 0

for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        ix1 = stoi[ch1]
        ix2 = stoi[ch2]
        prob = P[ix1, ix2]
        logprob = torch.log(prob)
        log_likelihood += logprob
        n += 1

nll = -log_likelihood / n
print(f'Negative Log Likelihood Loss: {nll.item():.4f}')

The Zero Probability Problem (Model Smoothing)

If we evaluate a completely novel word like andrejq, the bigram jq will have a count of 0 in our training set. This yields a probability of 0.0. The log of 0 is $-\infty$, causing an infinite NLL loss!
To prevent this, we apply Laplace Smoothing by simply adding a fake count (e.g., 1) to every cell in the matrix before normalizing: 

P = (N + 1).float() # Smoothing
P /= P.sum(1, keepdim=True)

7. Casting Bigrams as a Neural Network

The counting approach is elegant but rigid. It doesn't scale to larger contexts. To prepare for deeper models, we must re-frame the exact same bigram model as a differentiable neural network optimized via gradient descent.

1. Creating the Training Set

We extract all inputs (xs) and labels (ys) as parallel 1D tensors.

xs, ys = [], []

for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        xs.append(stoi[ch1])
        ys.append(stoi[ch2])

xs = torch.tensor(xs)
ys = torch.tensor(ys)
num = xs.nelement()

2. One-Hot Encoding

Neural networks cannot take categorical integer indices directly. If we input integer $1$ and $2$, the network thinks the second category is "twice as large" as the first. We must use one-hot encoding to project these indices into independent dimensions. 

import torch.nn.functional as F
# Shape becomes (num_examples, 27)
xenc = F.one_hot(xs, num_classes=27).float()

3. The Single Linear Layer

We initialize a weight matrix $W$ of shape $27 \times 27$. The forward pass is simply matrix multiplication. 

g = torch.Generator().manual_seed(2147483647)
# requires_grad=True tells PyTorch to track operations for backprop
W = torch.randn((27, 27), generator=g, requires_grad=True)

# Forward pass
logits = xenc @ W

Intuition: Logits and Softmax

The outputs of the linear layer are raw real numbers called logits. How do we interpret these?

In the counting model, we had raw counts $N$ and normalized them. Neural networks can output negative numbers, and counts can't be negative. So we define the logits to be equivalent to the logarithm of the counts.

To get actual fake counts, we exponentiate the logits ($e^{\text{logits}}$). Then, we normalize the rows to sum to 1. This exact sequence of operations—Exponentiate $\rightarrow$ Normalize—is the famous Softmax function.

8. The Full Neural Net Training Loop

We combine the forward pass, the Softmax formulation, the negative log-likelihood loss calculation, and the backward pass (gradient descent) into a standard PyTorch training loop. 

# Training parameters
learning_rate = 50.0

for k in range(100):
    # ---------------------------
    # 1. Forward Pass
    # ---------------------------
    logits = xenc @ W # Predict log-counts
    counts = logits.exp() # Fake counts
    probs = counts / counts.sum(1, keepdims=True) # Probabilities (Softmax)
    
    # Compute NLL loss (pluck the prob assigned to the correct next character)
    loss = -probs[torch.arange(num), ys].log().mean()
    
    # ---------------------------
    # 2. Backward Pass
    # ---------------------------
    W.grad = None # Zero out gradients from previous step
    loss.backward() # Compute gradients of Loss w.r.t W
    
    # ---------------------------
    # 3. Update Weights
    # ---------------------------
    W.data += -learning_rate * W.grad

print(f"Final Neural Network Loss: {loss.item():.4f}")

Regularization in Neural Networks

Remember Laplace smoothing in the count-based approach (adding $+1$ to all counts to flatten the distribution)? How do we achieve that in the neural network?
If we push all weights $W$ toward $0$, the logits approach $0$. Exponentiating $0$ yields a matrix of all $1$s (perfectly uniform counts). We do this by adding an L2 Regularization penalty (Weight Decay) to the loss function: 

# Loss with L2 Regularization (Gravity pushing weights to 0)
loss = -probs[torch.arange(num), ys].log().mean() + 0.01 * (W**2).mean()

9. Conclusion and Equivalence

By the end of the lecture, if you print the loss of the explicit counting model and the neural network model, they converge to the exact same number (~2.47).

We have mathematically proven that minimizing the negative log-likelihood over a single linear layer with one-hot encoded inputs optimizes a weight matrix $W$ to be functionally identical to the empirical log-counts matrix derived from statistical counting.

The critical difference? The neural network approach scales. In the next lectures, we will replace xenc @ W with MLPs, RNNs, and Transformers, increasing the model's capacity to absorb historical context far beyond a single character.
